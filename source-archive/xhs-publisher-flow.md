# 小红书评论发布员执行手册 v1（笨助手逐步照做版）

> 适用：仅在委员长输出 **`APPROVED TO POST`** 后，向已独立验证过的目标评论发布唯一、逐字定稿。  
> 目标：**宁可不发、如实失败，也绝不点错楼、改写定稿或谎报成功。**

## A. 开始前：三项硬检查（任一不通过立刻 `blocked`）

1. 从父任务结果中抄下并核对四样东西：
   - **完整原帖 URL**（必须带 `xsec_token`）
   - **目标评论作者**
   - **目标评论完整文字或至少唯一前 15 字**
   - **唯一逐字定稿**
2. 定稿必须带有 `APPROVED TO POST`。没有这句话，**不发布**。
3. 做文字保险检查：定稿必须与父任务逐字一致；不许自行增删字、改语气、加产品名、价格、URL、联系方式或营销词。

## B. 浏览器隔离与页面确认

```bash
export AGENT_BROWSER_SESSION="<当前任务ID>-xhs"
export AGENT_BROWSER_PIN_TAB=1
agent-browser set viewport 1920 1080
agent-browser open "<完整带 xsec_token 的 URL>"
agent-browser wait 3000
agent-browser snapshot -i -c
```

4. 在 snapshot 中同时确认：帖子内容、**目标评论作者**、**目标评论文字**，并先确认当前登录账号昵称/UID。若目标评论作者等于当前登录账号，立即停止：这是自评，绝不回复。若只看见相似评论、作者不对或文字不完整，继续展开/滚动；仍不能确认就停止并 `blocked`。
5. 找到**目标评论本身**附近的 `展开 N 条回复`，按 ref 点击并重新 `snapshot -i -c`。只核查该目标楼层及其子回复内没有我方账号既有回复；只要存在一条，即停止，不要重复回复。其他独立评论楼层的我方回复不影响本目标楼层。
6. 有弹窗时，只能在输入前按 snapshot 的关闭/确认 ref；输入后绝不按 Escape。

## C. 最关键：锁定正确楼层再输入

7. **只能点击目标评论同一行/同一评论块的「回复」按钮 ref。**
   - 不要点底部通用评论框。
   - 不要点别的评论旁的「回复」。
   - 点击后立即 `wait 300` + `snapshot -i -c`。
8. 必须从新 snapshot 看到回复上下文，确认显示「回复 <目标作者>」或能明确表明当前输入框属于目标评论。看不出来即停止，不猜。
9. 点击该回复编辑框 ref：

```bash
agent-browser click @<目标回复编辑框ref>
agent-browser keyboard type '<唯一逐字定稿>'
agent-browser wait 500
agent-browser snapshot -i -c
```

10. **发送前双重核对（缺一不可）：**
    - 编辑框内能看到完整定稿的开头、结尾和关键句；
    - 发送按钮是 enabled，且回复上下文仍是目标作者；
    - 若发现文字重复（例如输入了两遍）、不完整、跑到通用评论框或目标作者不对：不要发送。清空或刷新后从第 4 步重做；仍无法确定则 `blocked`。

## D. 发送：一次且仅一次

11. 使用最新 snapshot 中的发送按钮 ref：

```bash
agent-browser click @<发送ref>
agent-browser wait 3000
agent-browser snapshot -i -c
agent-browser get url
```

12. 点击发送后的页面跳转**不等于失败，也不等于成功**。绝不可因为跳转就再次发送。

## E. 只做初步留证，不自行宣称最终成功

13. 先看发送后的 snapshot：是否仍在同一 URL / 是否有发送成功提示 / 是否能看到新回复。
14. 回到**原始完整 URL**（不要自己拼裸 URL），等待 3 秒，snapshot；展开目标线程，检索定稿的前 12 个唯一字。
15. 找到时，只报告：`已提交，初步可见证据：<定位说明>`；最终是否正确由独立复核员判定。
16. 没找到时，只报告：`提交后无法初步定位，不重发，交独立复核和协调员分析`。**不得重复点击发送，不得用第二条评论补发。**

## F. 失败报告模板

```text
FAIL REPORT
status: 未定位目标 | 已有我方回复 | 输入框上下文不明 | 定稿不一致 | 发送后待复核
url: <完整 URL>
target_author: <作者>
target_excerpt: <目标评论前 15-30 字>
approved_draft: <唯一逐字定稿>
last_snapshot_evidence: <看到什么/没看到什么>
commands_executed: <关键步骤，例如：点击了哪个回复按钮、是否点击一次发送>
request: 交独立复核/协调员；未经协调员反馈绝不重发
```

## 禁止事项（违反即失败）

- 不许点错评论的「回复」。
- 不许把两次 `keyboard type` 叠加成重复内容。
- 不许发送前未确认目标作者和输入上下文。
- 不许自行改写委员长定稿。
- 不许在不确定时补发第二条。
- 不许把“点击发送”写成“发布成功”。
- 不许提产品名称、价格、链接，或明显营销引流话术。
- 不许使用 eval 写入、填表或点击提交；refs-first。

## 完成标准

发布员完成的是：在正确目标楼层**仅尝试一次**逐字提交，并交出可复现的定位证据或结构化失败报告。独立复核员才有权确认最终发布正确。
